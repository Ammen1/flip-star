# Postman collection

`FlipStar-API.postman_collection.json` — **376 requests across 34 folders**,
covering every route the backend serves.

Generated by introspecting Django's URL resolver rather than written by hand, so
it matches the application exactly: same paths, same HTTP methods, no invented
endpoints and none missing.

## Import

1. Postman → **Import** → both files in this directory:
   - `FlipStar-API.postman_collection.json`
   - `FlipStar-Local.postman_environment.json`
2. Select the **FlipStar — Local** environment (top right).
3. Run **Authentication → POST auth login**.

The login request has a test script that captures the token into the `token`
collection variable. Every other request inherits
`Authorization: Token {{token}}` from collection-level auth, so nothing else
needs configuring.

## Variables

| Variable | Default | Purpose |
|---|---|---|
| `baseUrl` | `http://127.0.0.1:8000` | Point at staging/production by changing this |
| `token` | *(empty)* | Set automatically by any login/register request |
| `username` / `password` | `admin` / `Admin12345!` | Seeded local superuser |
| `phone` | `0912345678` | Ethiopian number for the OTP flows |
| `tierId` | *(empty)* | Copy from `GET /api/v1/subscriptions/tiers/active/` |
| `mandateId` | *(empty)* | Returned by `POST /api/v1/direct-debit/create/` |

## Public endpoints are marked `noauth`

83 of the 376 requests hit views declaring `AllowAny`, and are marked
`auth: noauth` so collection-level auth does not apply to them.

This matters before you log in: `{{token}}` is empty, so
`Authorization: Token {{token}}` renders as a bare `Token ` header, and DRF
rejects that with:

```json
{ "detail": "Invalid token header. No credentials provided." }
```

That turns a working public endpoint — register, login, send OTP, the provider
webhooks — into a 401. The generator reads each view's `permission_classes` to
decide, so the marking stays correct as permissions change.

## Phone registration flow

Three steps, in order. All four phone formats work (`09XXXXXXXX`,
`+251XXXXXXXXX`, `251XXXXXXXXX`, `9XXXXXXXX`); the server normalizes.

1. **POST auth send otp** — in DEBUG the response includes `dev_code`, so you do
   not need a real SMS.
2. **POST auth verify otp** — pass that code.
3. **POST auth register phone** — returns a token.

Verification is single-use and expires 15 minutes after step 2. Running step 3
twice fails the second time by design.

## Trailing slashes are mandatory

Every route ends in `/`. Django runs with `APPEND_SLASH=True`, which redirects a
slashless GET — but **cannot** redirect a POST/PUT/PATCH without discarding the
body, so it raises instead:

```
RuntimeError: You called this URL via POST, but the URL doesn't end in a slash
and you have APPEND_SLASH set.
```

The collection stores the trailing slash as an empty final element of the `path`
array (`["api","auth","login",""]`), because Postman rebuilds the request URL
from `path`, not from `raw`. If you hand-edit a URL, keep the slash.

`scripts/generate_postman.py` preserves this, and the check that enforces it is
in the same script's verification notes.

## Authentication

DRF Token, **not** JWT or Bearer:

```
Authorization: Token 9944b09199c62bcf9418ad846dd0e4bbdfc6ee4b
```

Tokens expire after `AUTH_TOKEN_TTL_DAYS` (default 14 days). Any of these
captures one:

- `POST /api/v1/auth/login/` — username + password
- `POST /api/v1/auth/login-with-phone/` — phone + password
- `POST /api/v1/auth/register/`, `/register-with-phone/`, `/login-with-subscription-otp/`

App user passwords are **exactly 6 digits**. The seeded local admin is the
exception, since `create_superadmin` does not enforce that rule.

## Read this before running everything

**Webhook folders** are called *by* Telebirr and Onevas, not by clients. They are
included so you can replay payloads locally. Neither the Onevas webhooks nor the
Telebirr direct-debit webhook verifies a signature, so posting to them changes
subscription state. Do not run them against production.

**Danger Zone** holds two unauthenticated destructive endpoints that still exist
in the codebase:

| Request | Effect |
|---|---|
| `POST /api/v1/setup-admin/` | Creates a Django superuser. Defaults to `Admin123!`. |
| `POST /api/v1/cleanup-reels/` | Nulls media on **every** Reel and Campaign. |

They are in the collection because they are part of the live API surface, not
because they should be used. See [../security.md](../security.md).

## Known 500s

Five endpoints return 500 regardless of input. These are pre-existing
application defects, not collection errors:

| Endpoint | Cause |
|---|---|
| `GET /api/v1/subscriptions/tiers/` | `serializer_class = None  # Add serializer later` |
| `GET /api/v1/admin/subscriptions/` | Same |
| `GET /api/v1/reels/:id/` (missing id) | `retrieve` catches the 404 and returns 500 with a traceback |
| `GET /api/v1/boost/campaigns/:id/` | Reads `profile.gender` / `.age` / `.city`, which do not exist on `UserProfile` |
| `GET /api/v1/messages/conversations/:id/messages/` | Unguarded lookup on a missing conversation |

Working alternatives exist for the first two: `/api/v1/subscriptions/tiers/active/`
builds its response by hand.

## Regenerating

The collection is generated, not maintained by hand. After adding or changing
routes, regenerate rather than editing the JSON:

```bash
cd backend
python scripts/generate_postman.py
```

Request bodies live in a curated map inside that script, keyed by URL name. Add
an entry there when you add an endpoint that takes a payload; anything without
one gets an empty JSON body.
